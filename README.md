# 界构 · Big Building

一个 React + TypeScript 的本地跑团 RPG 最小版本。模型帮助理解行动，独立规则引擎决定结果。关闭模型后，游戏仍然完整可玩。

## 本地启动

需要 Node.js 22.13+（推荐 24 LTS）。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5173 。默认同时启动 React 开发服务（5173）和仅监听本机的推理桥接服务（5174）。这不是多人权威服务器。

模型配置写入被 Git 忽略的 `.env.local`，变量格式参见 `.env.example`。`DEEPSEEK_API_KEY` 只由 Node 进程读取，不能以 `VITE_` 开头。当前默认 `deepseek-flash`；请求直达 DeepSeek 官方 API。未配置凭据或服务失败时返回明确标注的本地规则建议，按钮玩法始终可用。

只运行网页、不启动模型桥接：

```sh
npm run dev:web
```

## 已实现

- 三名角色同机轮流操作，共享时间、地图与事件。
- 四个地点；普通攻击、三种职业技能、治疗、休整、经验与升级。
- 王子的正午刺杀计划、半小时一次的腐蚀、延迟传播的死讯。
- 三条可完成路线：原剧情的黑化王子；提前弑君并净化；主动让队员成为首领、其他角色继续作战。
- 第二场景「灵境回廊」；角色与物品保留、能量 70% 转换、试炼战斗。
- 自动本地存档、JSON 导入导出、固定种子与完整指令重放。
- 42-agent + DeepSeek 自由文本行动建议；模型只能选择已通过规则验证的行动，点击「确认执行」才改变世界。
- 桌面与窄屏布局；移动端可展开角色属性、技能升级和行囊。

## 建议试玩路线

1. 地图点击「秘典书库」，调查王座秘典。
2. 前往「荆棘王座」，两次技能攻击击败国王。
3. 可以净化王座，也可以确认让当前角色成为新首领。
4. 推进时间后，在「世界档案」观察王子因死讯而改变计划。
5. 前往「界隙之门」，进入灵境，击败守卫后返回。
6. 「旅程存档」中验证重放、导出或开始新旅程。

如需体验原剧情：新旅程中推进时间到 15:00，再前往王座挑战被腐蚀的王子。

## 工程检查

```sh
npm run build       # TypeScript + 生产构建
npm test            # 规则、Agent 边界、模型传输、HTTP 桥接测试
npm run agent:demo  # 真实 42-agent 运行时 + 脚本模型，无外部 API 调用
npm run agent:live  # 真实 DeepSeek 调用，需本地凭据，会产生 API 用量
```

命令行可附加 `-- --replay /absolute/path/save.json --intent "我想去书库"`。CLI 只提出建议，不修改浏览器旅程。

## 分层

```text
React 界面 ── 指令 ──► 纯 TypeScript 规则引擎 ──► 世界状态与事件
   │                      ▲
   └─ 自由文本 ─► 本地桥接 ─► 42-agent ─► DeepSeek
                   │                         │
                   └─ 校验后的行动候选 ◄─────┘
                              │
                         玩家确认后结算
```

- `src/engine/`：不依赖 React、Node、模型和网络的规则、数据与指令协议。
- `src/components/`：React 界面组件。
- `integrations/42-agent/`：Node 专用适配层、DeepSeek transport、开发桥接与测试。
- `vendor/`：从固定上游提交打包的 42-agent，保留许可证与来源说明。
- `docs/architecture.md`：机制约束、42-agent 评估与后续迁移边界。

## 首版的边界

当前是本地机制验证，不是联网产品。NPC 的自动行为仍由确定性时间/条件规则执行；真实模型用于玩家行动建议，尚未接管 NPC 决策。自然语言只能映射到已有动作，尚不支持任意新机制。

未实现：账号、多人同步、UGC 剧本编辑器、审核 Agent、动态数值平衡、桌面/原生 App 打包。世界中全知资料在界面明确标为主持人视角；模型观察数据按角色过滤。模型适配目前使用临时内存 Session，未做持久化推理会话或进程故障接管。

生产迁移时，权威服务器持有唯一世界状态并调用同一规则引擎；客户端只提交指令。服务端还需身份绑定、房间队列、事务持久化、限流和资产验证。本地存档可编辑，不作为未来跨玩家资产认证。

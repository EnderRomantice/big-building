# 架构梳理 · 2026-10-14

## 结论

保留 **React 本地状态 + 纯 TypeScript 规则内核 + Node 回合服务**。本次纠正了两个产品边界：玩家只操作自己；DeepSeek 从「玩家行动建议器」改为「在场 NPC 的决策者」。不需要为当前六个地点引入全局状态库、数据库、路由系统或通用剧本框架。

桌面左侧是自己的角色、武器攻击、技能、对话与折叠行囊，右侧是地点方格、在场人物/物品方格和记录。窄屏依次显示地图、当地对象、操作、记录。顶部只保留像素字体 Big Building 和旅程菜单。

## 完整数据流

```text
玩家点击地点/动作，或输入对话
  → useJourney.act（同一时刻只允许一个请求，支持取消）
  → POST /api/agent/turn：ReplayFile + Command
  → Node 重放 → execute 玩家动作 → 在场 NPC 队列
  → 为队首 NPC 建立观察 → 42-agent 临时 Session
  → DeepSeek 调用 npc_action（speak / attack / end）
  → execute 校验并结算 → 下一步/下一个 NPC
  → 返回整轮 Command[]
  → journeyReducer 检查 session、actor、revision、id
  → 全部成功后一次提交 → localStorage 保存指令历史
```

| 层 | 职责 | 边界 |
| --- | --- | --- |
| `engine/engine.ts` | 拥有者限制、武器/物品、伤害、时间、NPC 队列、重放 | 纯函数，无网络或模型；模型不能提交任意数值补丁 |
| `engine/actions.ts` | 动作候选，通过引擎试算确定合法性和成本 | UI 不复制一份战斗与移动规则 |
| `engine/turn.ts` | NPC 决策类型、允许选项、失败降级 | 降级是明确的规则回应，不伪造模型输出 |
| `game/journey.ts` | 唯一客户端提交入口、原子批次、存档迁移与替换 | 任一指令失败，整个批次不改变原世界 |
| `game/useJourney.ts` | 网络、取消、保存、错误与降级提示 | 旧请求不能写入另一段旅程；失败保留输入 |
| `components/` | 展示及操作意图 | 不能直接修改世界或选择他人作为行动者 |
| `integrations/42-agent/turn.ts` | NPC 观察、受限工具、运行时和循环终止 | 不持有权威存档，不执行文件、shell 或任意状态写入 |
| `integrations/42-agent/server.ts` | Host/Origin/JSON/大小检查、一次一回合、断连取消 | 本机推理桥接，不是线上多人服务器 |

## 回合为何能够结束

每次合法玩家行动后，规则引擎为当前场景活着的 NPC 建立队列。对话对象优先回应，其他在场 NPC 仍可自行回应；没有 NPC 时由旁白回应。

每个 NPC 可以说一句后结束，也可说话后继续攻击或结束。只有敌对 NPC 能攻击，伤害由规则计算。攻击后自动移出队列；已经说过话的 NPC 不能无限继续说话。全队列最多 8 步，单次模型请求最多 20 秒，总回合最多 60 秒。玩家死亡立即清空队列。正常工具决策完成后不再额外请求模型生成重复总结。

模型不可用、返回非法动作或超时：中立 NPC 结束，敌对 NPC 执行规则攻击，界面显示降级原因提示。用户取消则中止请求并放弃整个尚未提交批次，玩家动作与 NPC 反应不会只保存一半。导入包含未结束队列的记录时，可显式继续该队列。

这给模型的是台词与有限动作的选择权。NPC 无法通过一句话真的交出未定义商品、改变伤害或控制玩家。铁匠铺与商店只有明确实现的铁剑、药草拾取，没有虚构交易系统。

## 单人规则与旧存档兼容

旧版存档是固定种子与 `Command[]`。直接修改旧 `attack` 的语义会让已有战斗被重新计算，因此保留旧命令处理，并增加可重放的 `begin` 指令：保留已结算剧情与历史，把当前角色绑定为艾琳、初始化手持装备并进入新回合规则。此后的 `strike` 仅执行玩家攻击，NPC 决策以独立 `npc_turn` 记录结算。

客户端不提供角色切换，规则内核和 HTTP 回合入口都检查自己的 `playerId`；死亡后不会控制其他角色。此绑定只约束本地产品交互，不构成服务器身份认证。

NPC 输出的实际台词与行为写入命令历史。重新打开和导入存档只重放记录，不调用模型，所以随机战斗和模型响应都可复现。新模型响应本身并非确定性的。

## 观察与记忆

每个 NPC 获得自己的目标、知识、当前角色可见的场景与人物、同一地点最近 12 条非全知日志，以及当前允许动作。不给它随机数状态或远处 NPC 的隐藏计划。短会话以日志重建上下文，因此两次发送之间能接续对话，刷新后仍能读回已有对话。

这还不是严格的角色记忆系统：场景日志没有逐人听见/看见的可见性标签，长期对话会超出窗口；王子在远处的刺杀、腐蚀与消息传播继续用确定性事件规则。这些限制应在扩展剧情前解决，而不是让模型自由改写世界。

## 保留与迁移时机

| 当前设计/限制 | 判断与后续条件 |
| --- | --- |
| 规则内核独立于 React 和模型 | 合理；继续作为所有命令的唯一裁决者 |
| 每个候选动作试算整个世界，每个回合重放完整存档 | 小规模原型可接受；长局出现卡顿后拆只读预览与快照/增量指令 |
| 单次回合返回完整批次，NPC 回应在完成后一起显示 | 简单且保证原子性；需要逐句流式反馈时引入临时事件展示与最终确认协议 |
| 本地浏览器持有存档，多个标签页可覆盖 | 只适合单玩家单标签；多人前必须将状态移到权威服务，补身份、队列和持久事务 |
| v1 存档上限 2000 条指令，NPC 步骤也计数 | 够机制试玩；长旅程应版本化规则并做快照，不能随意更改旧命令数值 |
| 剧情规则和地点结构仍有硬编码 | 第三个实质不同剧本出现后再抽离数据与事件定义 |
| 临时 42-agent Session + 本地 Node 桥接 | 满足短回合；持久计划、离线世界与服务故障恢复需要更完整的调度和存储 |
| 旧 `/api/agent/advice` 与 CLI | 作为兼容示例保留，普通游戏已不经过建议确认流程 |

## 验证

自动化覆盖旧版剧情重放、新版单人迁移、拳头/铁剑数值、物品一次性消费、所有者限制、NPC 顺序和终止、对话上下文、超时取消、HTTP 边界、原子批次及过期请求。模型测试使用真实 42-agent 运行时配合脚本模型。

真实浏览器验证使用独立测试端口与存档，通过同一个本地桥接调用 DeepSeek，检查地点移动、自由对话及连续上下文。生产构建另行验证客户端不包含 Node 运行时或密钥。真实 API 的长期可用性和每次生成质量不由测试保证。

本轮结果：8 个测试文件、42 项测试全部通过；TypeScript 与生产构建通过。真实 DeepSeek 连续对话记住了玩家给铁剑取的名字；拾取并装备后，普通攻击造成 13 点伤害，NPC 自行发言并反击 6 点伤害，下一轮技能消耗 8 点能量。刷新后进度和对话保留，原有存档只做读取核对，未被测试覆盖。390px 窄屏检查无横向溢出。另有 HTTP 断连测试确认模型任务取消后服务能够接受下一回合。

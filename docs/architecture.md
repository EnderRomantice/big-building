# 最小版本的架构决定

## 规则权威

`execute(previous, command)` 是纯函数：校验输入、角色、地点、状态与资源，复制世界、结算行动、推进世界时间，最后提交一个新版本。失败不改变旧世界。命令 ID 防止重复执行，expectedRevision 防止过期建议作用于新状态。未来多人服务器还必须把版本比较与落库置于同一事务，并绑定真实玩家与角色；目前浏览器版并不提供反作弊能力。

随机数为固定种子的 LCG。它适合可重放机制验证，不适合生产竞技中的保密随机数。存档格式固定为 v1，记录初始种子和指令；不信任导入文件提供的数值状态。最多 2000 次动作，文件大小有限制。更大世界应改用快照、增量事件与索引。

## 动态世界

探索移动为 30 分钟，战斗/治疗/交涉为 10 分钟。内核逐分钟推进，以确保跨越事件时间点的长动作不漏事件。首版只有少量关键 NPC；扩大规模时迁移到事件优先队列，并维持同样的时间与优先级语义。

国王与王子都存活时，12:00 刺杀触发。王子初始腐蚀 40，之后每半小时 +10，到 15:00 变为敌对首领。玩家提前杀死国王后，王子在 30 分钟后才收到消息并改变计划。信息到达由状态驱动，模型不直接获得全局事件日志。

「接受王座」是经过界面确认的特殊分支：队员主动退休并生成敌对 NPC。该动作不向行动建议 Agent 开放。首版为了验证角色控制权边界，使用明确选择，而不是隐藏数值导致自动接管玩家。

主线可通过净化、击败黑化王子或击败堕落队员完成。角色可以杀死尚未黑化的王子并选择净化，不强行补造一个剧情首领。

## 资源与成长

资源转换使用 `floor(current * 0.7)`；各剧本的恢复行为恢复本世界原生能量，因此恢复带来的资源增加伴随明确时间成本。10 单位往返转换得到 4 单位，没有无成本转换套利。第一版仅验证同品阶的魔力/灵力映射，未实现多品阶经济。

角色升级、技能等级、伤害、防御与行动成本属于通用规则。两个场景共用同一模型。现有装备属性已包含在初始角色属性中，战利品为可跨剧本携带的纪念物，不提供未审计的隐藏加成。数值尚未经过正式平衡测试。

## 42-agent 的采用结论

采用为 **Node 端 Agent 运行时基座**。代码与文档显示它提供工具注册、模型/工具循环、每会话 FIFO、检查点、取消和保守恢复；这与我们的「Agent 提议，规则裁决」边界一致。

检查的版本：`42-club/42-agent@d4bdf6af52353a907426cb64c4c792a2be111c5e`，Apache-2.0。npm registry 当时没有 42-agent 的公开包，因此从该固定提交构建并打包到 vendor；没有修改上游代码。上游测试在本机结果：242 通过，3 跳过，0 失败。这是功能测试证据，不是集群高可用认证；未运行带外部数据库的生产故障演练。

它明确定位为单进程运行时，不能替代房间权威状态、跨进程调度、身份授权或数据库事务。不会将它放进 React bundle，也不会让 SessionStore 成为游戏资产数据库。

当前适配使用真实 `AgentRuntime`、`AgentLoop`、`ToolRegistry` 与 `InMemorySessionStore`，每次建议是短会话。真实 DeepSeek 使用公开的 `AdaptedModelClient` 编解码边界，直接访问官方 API，关闭推理模式，最多四轮工具交互，每次输出上限 1024 token。45 秒可取消超时。未来持久 Agent 可以替换 SessionStore，但应继续隔离游戏状态。

只注册两个工具：

- `read_observation`：读取当前角色观察和合法行动列表。没有 shell、文件写入、任意 MCP 或修改世界的能力。
- `propose_action`：只能选择一个由宿主提供的合法行动索引，返回建议。不能传入伤害、金币、角色所有权或状态补丁。模型输出文本不会被解析成世界变化。

候选动作在内核的复制世界上校验，不提交结果。玩家确认时再次检查当前角色和世界版本并结算，拒绝过期建议。模型失效时返回显式标注的本地规则建议；取消不会自动执行动作。

玩家观察只含自身、小队、当前位置和可见 NPC，没有远方 NPC 意图、随机种子或全知事件日志。为后续 NPC 规划提供了 `npcObservation`，当前仅返回 NPC 自身知识与同地可见人物，尚未接入自动 NPC 决策。

## 本地推理桥接

5174 端口仅监听 127.0.0.1，5173 Vite 反向代理 API。校验 Host、Origin、请求类型与大小；同一时间只处理一次建议。秘密只从 Node 侧 `.env.local` 读取，文件权限为 0600，并被 Git 忽略。凭据不进入客户端 bundle、状态存档、日志或导出包。

浏览器提交已验证格式的旅程，桥接通过重放得到观察状态，再调用 Agent。此设计服务于本地开发；生产应由权威世界服务提供可信快照，不能接收浏览器自报的资产与历史。

## 验证范围

单元/集成测试覆盖三条主线分支、消息延迟、腐蚀、确定性重放、版本冲突、重复指令、非法参数、资源不足、治疗与升级、跨剧本转换与远方事件，以及 Agent 越权工具、伪造数值、观察隔离、失败兜底、取消超时、官方模型传输与本地 HTTP 边界。

浏览器验证覆盖移动、调查、技能攻击、真实 DeepSeek 建议、玩家确认后结算、升级与净化结局。外部 DeepSeek 的可用性与输出内容不由本地单元测试保证。

# 架构梳理 · 2026-10-14

## 结论

保留 **React 本地状态 + 纯 TypeScript 规则内核 + Node 回合服务**。本次纠正了两个产品边界：玩家只操作自己；DeepSeek 从「玩家行动建议器」改为「在场 NPC 的决策者」。不需要为当前九个地点引入全局状态库、数据库、路由系统或通用剧本框架。

桌面左侧是自己的角色、武器攻击、技能、对话与折叠行囊，右侧是按种子生成的不规则区域地图与路线预览、在场人物/物品方格和记录。攻击与技能先进入选择对象状态，再点击合法人物提交；取消、换场景或换存档会清除待选动作。对话不绑定预选人物，默认广播给当前场景，在场 NPC 各自决定是否回应。窄屏依次显示地图、当地对象、操作、记录。顶部只保留像素字体 Big Building 和旅程菜单。

## 完整数据流

```text
玩家点击地点/动作，或输入对话
  → useJourney.act（同一时刻只允许一个请求，支持取消）
  → POST /api/agent/turn：ReplayFile + Command
  → Node 重放 → execute 玩家动作 → 在场 NPC 队列
  → 为队首 NPC 建立观察 → 42-agent 临时 Session
  → DeepSeek 调用 npc_observe / speak / attack / ceasefire / move / end
  → execute 校验并结算临时世界 → 工具返回最新观察与动作结果
  → 同一 NPC Session 继续决策 → 明确结束后才进入下一 NPC
  → 返回整轮 Command[]
  → journeyReducer 检查 session、actor、revision、id
  → 全部成功后一次提交 → localStorage 保存指令历史
```

| 层 | 职责 | 边界 |
| --- | --- | --- |
| `engine/engine.ts` | 拥有者限制、武器/物品、伤害、时间、NPC 队列、重放 | 纯函数，无网络或模型；模型不能提交任意数值补丁 |
| `engine/actions.ts` | 动作候选，通过引擎试算确定合法性和成本 | UI 不复制一份战斗与移动规则 |
| `engine/turn.ts` | NPC 决策类型、允许选项、失败降级 | 降级是明确的规则回应，不伪造模型输出 |
| `game/journey.ts` | 唯一客户端提交入口、原子批次、存档迁移与替换 | 任一指令失败，整个批次不改变原世界 |
| `game/useJourney.ts` | 网络、取消、保存、错误与降级提示 | 旧请求不能写入另一段旅程；失败保留输入 |
| `components/` | 展示及操作意图 | 不能直接修改世界或选择他人作为行动者 |
| `integrations/42-agent/turn.ts` | NPC 观察、受限工具、运行时和循环终止 | 不持有权威存档，不执行文件、shell 或任意状态写入 |
| `integrations/42-agent/server.ts` | Host/Origin/JSON/大小检查、一次一回合、断连取消 | 本机推理桥接，不是线上多人服务器 |

## 回合为何能够结束

每次合法玩家行动后，规则引擎为当前场景活着的 NPC 建立队列。对话对象优先回应，其他在场 NPC 仍可自行回应；没有 NPC 时由旁白回应。

每个 NPC 使用同一个 42-agent Session 连续调用工具，先执行再反馈，而不是选好一句台词就强制终止。说话和攻击都不自动结束；停战将自己的关系改为中立，移动只改变自己的地点并结束本轮。`npc_end` 明确交还回合。每种非终止动作每轮最多一次，每人最多 8 次模型回应、6 条动作记录；单 NPC 最多 45 秒、整轮最多 60 秒。玩家死亡立即清空队列。只有终止动作完成后才本地收尾，不再额外付费生成重复总结。

`npc_step` 的所有规则和数值在纯引擎中验证。模型无法更改自己身份、控制另一名 NPC 或代替玩家行动。失败工具以错误结果返回同一会话，让模型修正；无明确终止或超出预算视为失败。单 NPC 的临时动作在失败时丢弃，避免降级时重复攻击。客户端上限 43 条命令，可覆盖玩家动作和全部 NPC 的有界执行。
模型不可用、返回非法动作或超时：如果玩家正在发送对话，服务返回明确的 503 错误及原因代码，整轮不提交，客户端保留输入；移动、攻击等其他行动保留规则降级，中立 NPC 结束、敌对 NPC 执行规则攻击，界面显示具体原因。用户取消则中止请求并放弃整个尚未提交批次，玩家动作与 NPC 反应不会只保存一半。导入包含未结束队列的记录时，可显式继续该队列。

这给模型的是台词与有限动作的选择权。NPC 无法通过一句话真的交出未定义商品、改变伤害或控制玩家。铁匠铺与商店只有明确实现的铁剑、药草拾取，没有虚构交易系统。

## 单人规则与旧存档兼容

旧版存档是固定种子与 `Command[]`。直接修改旧 `attack` 的语义会让已有战斗被重新计算，因此保留旧命令处理，并增加可重放的 `begin` 指令：保留已结算剧情与历史，把当前角色绑定为艾琳、初始化手持装备并进入新回合规则。此后的 `strike` 仅执行玩家攻击，NPC 决策以独立 `npc_step` 记录结算。已有 `npc_turn` 保留原语义，兼容旧记录和规则降级。

客户端不提供角色切换，规则内核和 HTTP 回合入口都检查自己的 `playerId`；死亡后不会控制其他角色。此绑定只约束本地产品交互，不构成服务器身份认证。

NPC 输出的实际台词与行为写入命令历史。重新打开和导入存档只重放记录，不调用模型，所以随机战斗和模型响应都可复现。新模型响应本身并非确定性的。

## 观察与记忆

每个 NPC 获得自己的目标、知识、当前角色可见的场景与人物、同一地点最近 12 条非全知日志，以及当前允许动作与自己的上次意图摘要。每个动作的简短意图及工具名随日志保存，可展开查看；不展示模型内部推理过程。不给它随机数状态或远处 NPC 的隐藏计划。短会话以日志重建上下文，因此两次发送之间能接续对话，刷新后仍能读回已有对话。

这还不是严格的角色记忆系统：场景日志没有逐人听见/看见的可见性标签，长期对话会超出窗口；王子在远处的刺杀、腐蚀与消息传播继续用确定性事件规则。这些限制应在扩展剧情前解决，而不是让模型自由改写世界。

## 保留与迁移时机

| 当前设计/限制 | 判断与后续条件 |
| --- | --- |
| 规则内核独立于 React 和模型 | 合理；继续作为所有命令的唯一裁决者 |
| 每个候选动作试算整个世界，每个回合重放完整存档 | 小规模原型可接受；长局出现卡顿后拆只读预览与快照/增量指令 |
| 单次回合返回完整批次，NPC 回应在完成后一起显示 | 简单且保证原子性；需要逐句流式反馈时引入临时事件展示与最终确认协议 |
| 本地浏览器持有存档，多个标签页可覆盖 | 只适合单玩家单标签；多人前必须将状态移到权威服务，补身份、队列和持久事务 |
| v1 存档上限 2000 条指令，NPC 步骤也计数 | 够机制试玩；长旅程应版本化规则并做快照，不能随意更改旧命令数值 |
| 剧情规则和地点结构仍有硬编码 | 第三个实质不同剧本出现后再抽离数据与事件定义 |
| 临时 42-agent Session + 本地 Node 桥接 | 满足短回合；持久计划、离线世界与服务故障恢复需要更完整的调度和存储 |
| 旧 `/api/agent/advice` 与 CLI | 作为兼容示例保留，普通游戏已不经过建议确认流程 |

## 验证

自动化覆盖旧版剧情重放、新版单人迁移、拳头/铁剑数值、物品一次性消费、所有者限制、NPC 顺序和终止、对话上下文、超时取消、HTTP 边界、原子批次及过期请求。模型测试使用真实 42-agent 运行时配合脚本模型。

真实浏览器验证使用独立测试端口与存档，通过同一个本地桥接调用 DeepSeek，检查地点移动、自由对话及连续上下文。生产构建另行验证客户端不包含 Node 运行时或密钥。真实 API 的长期可用性和每次生成质量不由测试保证。

## 错误处理与边界

先前的「每步独立决策」实现曾在第二轮纠正工具参数成功后因轮数耗尽丢弃结果。现由完整 NPC 会话替代；8 次模型回应之外保留一轮本地终止。DeepSeek 关闭 thinking，NPC 工具组使用 `tool_choice: required`。API 选项依据 [DeepSeek 官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

网络、限流和服务故障有限重试一次；凭据和额度错误直接报告。对话失败整轮回滚，非对话允许明确规则降级。错误仅使用应用定义的消息，服务日志只记录 NPC、错误代码及耗时，不写密钥、输入原文或上游错误正文。

仍是玩家行动驱动的在场 NPC 回合，不是后台永远运行的所有角色模拟。远处的王子刺杀仍由规则驱动。NPC 能决定当前支持的真实动作，尚无交易、召唤守卫或任意任务生成工具，台词也不应声称已经完成这些事。

## 区域地图与道路规则

`engine/geography.ts` 提供纯函数生成器与寻路：使用独立 PRNG 生成大陆轮廓和区域种子点，Voronoi 半平面裁剪得到无缝区域；共享边界只扰动一次，邻区反向复用。世界包含区域，区域包含地点。几何结果按 seed 缓存（最多 24 张），不消耗战斗 RNG；前后端使用同一份算法。

地图上展示的折线道路也用于距离计算。Dijkstra 选择当前可通行的最短耗时路线，过滤未解锁道路以及敌对的中间地点。玩家 `move` 每经过一段道路就推进游戏时间，再检查新到达地点和区域；远处剧情事件仍会发生，新出现的敌人可以中断旅程。最终只为实际到达地点建立 NPC 队列。没有现实时间计时器，也没有额外的跨区 API。

`RegionMap` 负责地图浏览、目的地选择和路线预览。黑白地貌由 `REGION_TEXTURES` 配置每区颗粒间距、半径、模糊量和透明度，SVG pattern/filter 仅作用于纹理，文字与道路保持锐利。确认移动仍通过原有 `/api/agent/turn`，服务端重放后重新寻路与验证；请求不接受客户端指定距离、时间或状态补丁。区域切换与浏览不发送请求，旧请求的会话隔离规则保持不变。

重放文件新增可选 `mapVersion`，缺省为旧版 0；新旅程从版本 1 开始。`World.initialMapVersion` 保存初始规则，`mapVersion` 保存当前规则。旧版历史重放后，`ensureAdventure` 增补可重放的 `enable_map` 指令，不消耗时间，不覆盖未结束 NPC 队列。导出使用初始版本，迁移后的移动通过历史中的迁移位置切换语义。将来更改生成器必须引入新的地图版本，不能改写已有种子的规则。

新增验证覆盖多种种子的区域面积与地点归属、道路连通、符文条件、路线耗时、沿途敌人、新出现敌人的中断、客户端/HTTP 成本一致、地图迁移与完整重放。界隙穿越继续使用原有世界切换规则。NPC 移动只补道路检查，尚未新增 NPC 在途模拟；新地点目前没有额外任务或人物内容。


## 地图交互、治疗与输入模式

地点点击直接使用现有 `Modal` 显示路程和确认，取消不产生请求；移除地图视图切换与点击区域缩放。区域悬停/键盘聚焦展示情报，点击固定卡片。`regionIntel` 从现有地点、人物和可交互资源生成信息，已拾取物品不再列出；区域基础危险等级在有敌对 NPC 时提高，不新增虚构可采集资源。

左侧动作选择改为 attack / skill / heal。治疗使用新命令 `mend`，对象可为自己或在场存活 NPC，恢复 min(5, 缺失生命)，消耗 6 能量与 10 分钟；完成后仍走 NPC 回合。旧 `heal` 的 16 HP 规则只用于历史重放/旧小队协议，当前单人回合服务拒绝直接提交它，避免导入存档时改变过去结果。

输入框维护 action / say 两份草稿。Say 继续发送 `say` 命令；行动模式先调用 `/api/agent/advice`，模型只能从 `legalOptions` 提议一个动作，客户端显示成本及攻击警告，用户确认才通过 `/api/agent/turn` 结算。取消、无可执行动作和识别失败保留输入；世界版本改变后旧建议不可确认，旅程替换则重建整个输入组件。行动识别与执行共用请求锁和取消控制器。

NPC 观察增加 `playerInput`：say 明确标为未执行的台词，action 携带已经由引擎结算的指令。提示词区分两种输入，不能把「我攻击了你」等台词当作已经发生的伤害。新测试覆盖 5 HP 治疗、生命上限、目标合法性、能量、旧命令重放、模型观察的模式区分与资源情报更新。


## 统一内容区

`App` 管理 scene / map / person 三种纯界面状态，默认 scene。文字导航按需挂载 `RegionMap`；`SceneGrid` 仅渲染在场人物与物品，普通点击 NPC 打开 `CharacterDetails`，选技能时则继续作为行动目标。左侧角色姓名同样打开详情。详情从当前世界读取属性、装备及最近台词，不请求模型、不改变历史或游戏时间。切换地图或查看人物取消未完成的目标选择，选择技能自动返回场景。旅程会话、地点或世界变化后回到场景，避免旧上下文滞留；左侧对话草稿不随右侧切换而丢失。


## 九阙争衡与局部探索（当前版本）

本节取代上文旧篇专属的全知地图和不可切换角色交互说明；旧规则实现保留用于兼容。

`succession.ts` 提供十城、五十镇、建筑、道路、人物社会关系和区域物品/技能定义，`stats.ts` 为玩家、人物、怪物提供共同数值工厂与伤害函数。城市设定独立编写，普通居民以地方和职业模板组合生成。新世界使用 `campaign: succession-v1`、`initialHero` 标识规则和开局；`execute` 分派给 `successionEngine.ts`，避免改变旧历史。今后修改已保存行为语义需要新版本。

新篇在规则内处理相邻旅行、足迹、好感、同地见证者影响、购买与库存、学习和施法、付费休整、升级、证词与议会立场。新增 `assault` 允许攻击友善对象，旧篇当前单人交互也使用它；历史 `strike`、`attack` 保留原语义。剧情台词不具有生成奖励、改变库存或完成任务的权限。

`worldContent.ts` 提供跨剧本的已访地点、邻路线索、可见名称与物品。当前 UI 使用 `LocalMap`，只呈现当前地点与相邻道路；未访问目的地始终显示线索，玩家到达后才揭名。`RegionMap` 和旧地形生成器保留为历史实现，不再挂载世界地图。模型移动工具只接收当前允许的目的地，新篇只允许邻接地点，未知名称在观察中遮盖。客户端源代码仍包含完整内容定义；探索隐藏是游戏呈现规则，不是保密机制。

Home 管理剧本与角色选择。`journeySlot` 按剧本版本与初始角色建立独立本地存档，`SAVE_KEY` 保留当前旅程以兼容旧入口；切换时保存旧槽并重放目标槽，不共享角色装备、铜钱或足迹。顶栏头像由本地称呼首字生成，不代表线上登录账户。新篇导入/导出携带初始角色和内容版本，重放不调用模型。

回合服务仍在服务端重放并结算，再由客户端校验原子批次。570 个实体不是 570 个常驻 Agent：只启动在场人物队列，远处消息按时间阈值结算。当前 2000 指令上限与全历史重放仍在，长篇存档后续需要版本化快照。区域商品库存为有限静态库存，没有后台生产或动态市场。

新回归覆盖内容规模与道路连通、同数值模板、友善攻击与好感、探索遮名与移动、购买学习施法、继位条件，以及角色存档隔离和重放。真实浏览器另行验证友善攻击、未知道路抵达揭名与 Home 换角恢复。


## 职业体系、跨世界角色与移动反馈

`careers.ts` 定义三个体系、九个玩家职业和三类怪物职业，以及通用技能、职业树、技能点与跨界档案校验。`enable_careers` 是显式迁移命令：旧记录先按旧语义重放，在迁移位置初始化职业和共同数值模板，后续记录保留职业规则。`careerCombat.ts` 在两个剧本引擎的正常时间/事件/回合结算前处理 `invoke`、`unlock_skill` 和 NPC 战术行动；普通攻击同样经过护盾吸收，死亡奖励由原剧本结算。

冷却使用 `combatRound` 与每个技能的 `readyAt`，一次玩家行动推进一轮，研习不推进；NPC 的 `turn.actions` 约束每轮一次主要行动。工具观察提供具体职业、已学技能、合法目标、剩余冷却、气力、护盾和上次战术，工具执行仍以规则为准。不可移动的灵境 NPC 不注册移动工具，避免空目的地枚举。旁白不能通过技能工具控制任何人物。

`CharacterRecord` 只携带 id、名字、职业、等级、经验和已解锁技能，不携带世界剧情或物品。`adopt_character` 将经过校验的角色档案绑定到新世界，并在旧世界回归时同步成长；不允许同一世界替换另一个角色或把等级/技能倒退。每次绑定/同步写入重放历史，HTTP 服务无需读浏览器中的全局角色列表也能重建。跨世界角色列表存在 `big-building:characters:v1`，世界槽使用 characterId；存储合并保留更高成长和已有技能，并验证技能点，不能静默覆盖冲突职业。这是本地单玩家档案，不是防作弊账户系统。

`useJourney.movingTo` 仅跟踪尚未提交的移动请求，成功、失败和取消都在 finally 清理。`App` 发起移动时保持 map 内容，`LocalMap` 把目标道路与路径点标为 busy 并灰显，其他道路禁止重复提交。路径点的可点击范围与路线装饰分开；成功提交后地点 context 改变，内容区回到场景。移动请求与 NPC 回应仍作为一个原子回合提交，加载反馈不修改游戏时间和实际位置。


真实模型的职业回合验证发现：每个工具结果重复携带完整观察，可能在第三、四次决策时触及运行时的 32K 保守输入预算。现初次提示保留完整设定和技能说明，后续 `turnFeedback` 只传动态数值、冷却、合法目标与本次结果；场景记忆至多 12 条、总计 1200 字。回归使用与真实客户端一致的预算覆盖长历史中的八次决策，不通过虚报模型上下文上限绕过限制。模型工具编号在应用边界归一化，避免供应方跨回应复用编号破坏运行时关联。
